## 2. Anthropic subscription auth

**Reworked mid-implementation** (see design.md Context "Superseded finding"): a raw-HTTP approach using a `claude setup-token` bearer token was built, then found to be both rejected by the Messages API and a Consumer ToS violation, and was replaced with a `claude -p` subprocess provider modeled on OpenClaw's own implementation. `providers/anthropic.rs` reverts to its unmodified Stage 1 (API-key-only) shape. The original standalone `claude_cli.rs` (status detection) was later merged into `claude_code_cli.rs` itself — it had no other caller and its only genuinely reusable piece (`map_spawn_error`, generic across any CLI-backed provider) moved to a new small `cli_process.rs` instead, so Group 3's Codex work can share it without importing from a Claude-named module.

- [x] 2.1 Trim the status-detection helper to just `check_logged_in()`/`parse_auth_status()` (now inside `claude_code_cli.rs`, see note above); remove the token-minting functions and their tests. Verify `cargo test -p fleet-snowfluff-ai` still passes with the trimmed module.
- [x] 2.2 Revert `providers/anthropic.rs` to its Stage 1 shape (`api_key: String` field, single `x-api-key` header path, `Anthropic::new(api_key, base_url, model)`); remove the `AnthropicAuth`/`resolve_auth_header`/`apply_auth` machinery and the subscription-header tests added in the reworked-away first pass.
- [x] 2.3 Add `providers/claude_code_cli.rs` with a `ClaudeCodeCli: AiProvider` implementation that spawns `claude -p --system-prompt <persona> --disallowedTools <fixed deny-list> --strict-mcp-config --setting-sources "" --output-format stream-json --include-partial-messages [--resume <session-id>] "<latest user message>"`, extracting the system prompt and latest user message from the `messages` argument. Extract the `content_block_delta`/`text_delta`-matching logic already in `anthropic.rs`'s `parse_sse_line` into a shared function both implementations call, applied here to the unwrapped `event` field of each `{"type":"stream_event","event": ...}` line. Verify by parsing the literal fixture lines captured live this session (a `message_start`/`content_block_start`/`content_block_delta`/`content_block_stop`/`message_delta`/`message_stop`/`result` sequence) into the expected `StreamChunk`s.
- [x] 2.4 Track the session id: capture the `session_id` field present on every parsed line into an `Arc<Mutex<Option<String>>>` on `ClaudeCodeCli`, exposed via an inherent `session_id(&self) -> Option<String>` (not part of the `AiProvider` trait); pass `--resume <id>` on construction when a prior id is supplied. Verify with a unit test that feeds two literal fixture streams through two constructed instances and asserts the id captured from the first is what gets passed to the second.
- [x] 2.5 Map CLI-level failures (binary missing → `RuntimeUnavailable`; not logged in → `SubscriptionExpired`; a failed `--resume` → treated as "start fresh," not a hard error, per the "Session continuity" requirement's fallback scenario) to the appropriate `ProviderError` variants or fallback behavior; verify with tests over literal fixture outputs (still unverified against a real quota-exhausted/rate-limited response, since that wasn't observed live — documented as an assumption, same caveat style as the auth-status work).

- [x] 2.7 Fix `ClaudeCodeCli::list_models()` returning an empty list (caught in review: this would leave the settings UI with no way to select a model for this profile, unlike every other configured provider). Return Claude Code's own known `--model` aliases instead (`sonnet`, `opus`, `fable`, `haiku`). Verify with a test asserting all four aliases are present.
