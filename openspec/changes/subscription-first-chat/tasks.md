## 2. Anthropic subscription auth

**Reworked mid-implementation** (see design.md Context "Superseded finding"): a raw-HTTP approach using a `claude setup-token` bearer token was built, then found to be both rejected by the Messages API and a Consumer ToS violation, and was replaced with a `claude -p` subprocess provider modeled on OpenClaw's own implementation. `providers/anthropic.rs` reverts to its unmodified Stage 1 (API-key-only) shape. The original standalone `claude_cli.rs` (status detection) was later merged into `claude_code_cli.rs` itself — it had no other caller and its only genuinely reusable piece (`map_spawn_error`, generic across any CLI-backed provider) moved to a new small `cli_process.rs` instead, so Group 3's Codex work can share it without importing from a Claude-named module.

- [x] 2.1 Trim the status-detection helper to just `check_logged_in()`/`parse_auth_status()` (now inside `claude_code_cli.rs`, see note above); remove the token-minting functions and their tests. Verify `cargo test -p fleet-snowfluff-ai` still passes with the trimmed module.
- [x] 2.2 Revert `providers/anthropic.rs` to its Stage 1 shape (`api_key: String` field, single `x-api-key` header path, `Anthropic::new(api_key, base_url, model)`); remove the `AnthropicAuth`/`resolve_auth_header`/`apply_auth` machinery and the subscription-header tests added in the reworked-away first pass.
- [x] 2.3 Add `providers/claude_code_cli.rs` with a `ClaudeCodeCli: AiProvider` implementation that spawns `claude -p --system-prompt <persona> --disallowedTools <fixed deny-list> --strict-mcp-config --setting-sources "" --output-format stream-json --include-partial-messages [--resume <session-id>] "<latest user message>"`, extracting the system prompt and latest user message from the `messages` argument. Extract the `content_block_delta`/`text_delta`-matching logic already in `anthropic.rs`'s `parse_sse_line` into a shared function both implementations call, applied here to the unwrapped `event` field of each `{"type":"stream_event","event": ...}` line. Verify by parsing the literal fixture lines captured live this session (a `message_start`/`content_block_start`/`content_block_delta`/`content_block_stop`/`message_delta`/`message_stop`/`result` sequence) into the expected `StreamChunk`s.

## 3. OpenAI/Codex subscription auth (experimental)

- [x] 3.1 (reworked from the original wording once live research corrected two assumptions — see design.md Context "Correction to an earlier pass") Added `providers/codex.rs` with a `Codex: AiProvider` implementation that spawns `codex exec --json --sandbox read-only -c model_instructions_file=<temp file with the persona> [resume <id>] "<latest user message>"`. Since Codex's assistant text arrives as one complete `item.completed`/`agent_message` event, not deltas, the reply is chunked client-side after the fact (reusing `Mock::chunk_text`) so the stream still paces out over time per the "Streaming responses" requirement's new scenario for this case. Verified by parsing literal fixture lines built from Codex's own published event-shape documentation (`thread.started`, `item.completed`/`agent_message`, `turn.failed`, top-level `error`, and several ignored event types) — not a live capture, unlike the Anthropic fixtures, since no subscription was available.
- [x] 3.2 Added `codex login status` detection (exit-code-based, unlike `claude auth status --json`'s structured output) mapping to the same `ProviderError` variants as the Anthropic path, sharing `cli_process::map_spawn_error` for the missing-binary case. Verified with tests over literal fixture outputs, same style as the Anthropic work.
- [x] 3.3 Investigated: no flag exists to disable tool access outright, but `--sandbox read-only` (the default) prevents shell command *execution* entirely (confirmed via documentation) — narrower than Claude's `--disallowedTools` but covers the highest-severity risk (arbitrary command execution). Whether the reply *text* still narrates/proposes tool use even though it can't execute is unconfirmed and documented as an open, experimental-gated question. Also investigated (not originally scoped, but the same class of question): no `--system-prompt` equivalent exists at all — `-c model_instructions_file=<path>` (OpenClaw's own mechanism) is used instead, with its precedence-vs-`AGENTS.md` behavior similarly unconfirmed.
- [x] 3.4 Added `ProviderProfile::is_experimental()` in `settings.rs` (a profile-level fact, not an `AiProvider` trait method) returning true only for `(OpenAi, Subscription)`. Verified with a test asserting exactly that combination reports experimental and every other combination does not.
