## 4. Dispatcher, limits and the job run

- [ ] 4.1 Implement `JobDispatcher` on the shared `Clock`: find due triggers, apply the grace window, and record missed runs as skipped with a reason. Verify with a synthetic clock: an on-time and a slightly late fire run, a fire missed while the app was closed is skipped and logged, and nothing is caught up.
- [ ] 4.2 Add the run limits: no overlap per job, one agent job per backend and two overall with a queue of at most ten (a full queue skips the new run and logs it), reminders bypassing the queue, a local-backend run waiting for an in-flight chat reply on the same backend only, a time limit and turn cap, no retries, and disabling the triggers after three consecutive failures with a notification. Verify each rule with tests on the fake clock and a fake executor, including a local job running in parallel with a cloud chat, an 11th waiting job being skipped, and a run 59 seconds late running while one 61 seconds late is skipped.
- [ ] 4.3 Build the per-run registry from the allow list with the hard-excluded set removed afterwards (shell, job tools, delegation, MCP connect, memory writes), and MCP tools only if individually ticked. Build the job-specific read-file and list-directory tools with their root fixed to the project directory plus the job's output folder and no confirm fallback. Verify that an excluded tool is absent even when the stored list names it, an unticked MCP tool is absent, the registry does not change during a run, a path outside the allowed roots is refused with no prompt (including via `..` and a link), and with no project directory only the output folder is readable.
- [ ] 4.4 Add the output-folder write tool, reusing the path confinement from `file_tools.rs`, with size and count bounds. Verify with tests for a relative path, a parent reference, a symbolic link out of the folder, an absolute path elsewhere, and an over-size write.
- [ ] 4.5 Implement the agent-job executor: plain system prompt plus the job prompt, no persona, history or memory digest, the pinned profile with no fallback (only local and API-key profiles are accepted; a CLI-backed profile is rejected at approval and at run time), the acknowledgment and disclosure-revision check at run time, and recording of tool names and output. Verify with a scripted provider: a run records output and tool names only, a missing profile fails with a reason and falls back to nothing, a withdrawn acknowledgment fails with the needs-acknowledgment reason, and nothing reaches memory or chat history.
- [ ] 4.6 Wire the dispatcher into the application runtime with startup and shutdown, per-backend in-flight signals, and the job store location. Verify with an integration test that starts the runtime on a fake clock and fires a job end to end.
- [ ] 4.7 Take an exclusive lease on a lock file beside `jobs.db` before dispatching, held for the process lifetime, so a second instance does not dispatch. Verify with a test that starts two dispatchers on one store and shows each due trigger producing one run, and that the second reports it is not dispatching.
