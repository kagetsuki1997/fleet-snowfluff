## Why

A Conversation is supposed to be resumable across different runtimes with a shared context, per `docs/fleet-snowfluff-feature-planning.md`'s domain model — but today only the chat transcript (user/assistant text) and, for CLI-backed profiles, the single _latest_ session per provider (`.sessions.json`, one row per profile, overwritten in place) are persisted. There is no record of which profile handled a turn, what route it took (direct, escalated, a discarded `mix`-mode local attempt), what a tool call actually did, or why a turn ended the way it did. `ContextManager` exists (`build_context`/`record_execution`) but is still unwired — `chat_commands.rs` calls `prompt::assemble_messages` directly — because nothing needed more than the transcript until now. A real consumer exists now: a tool-calling turn's own activity (e.g. `read_file` finding a project empty) is invisible to the very next turn, which only sees the model's own prose summary of it, because `AgentRuntime::run` returns only the final text and discards everything else when it returns. Separately, the application can only ever resume the single most recent conversation; there is no way to see, reopen, or delete an older one.

## What Changes

- Replace the per-conversation `.sessions.json` "latest session" sidecar with an append-only `<ts>_<id>.executions.jsonl` log: one `start` record and one `end` record per `Execution` (every turn, uniformly, including a discarded `mix`-mode local attempt that escalates or fails — this log is an internal audit trail, not the user-facing transcript, and the existing rule that only the winning attempt reaches the chat log does not apply here). An `Execution` record carries its route (direct / mix-local / fallback / tool-calling), profile, working directory, external session reference where applicable, status (`Completed` / `Errored` / `Cancelled` / `Escalated`), and a trace of any tool calls made. The "latest usable session per profile" view `cli-session-continuity` relied on is now derived by scanning this log, not read from a separate file.
- **BREAKING** (internal format only, not user-visible): the on-disk `.sessions.json` sidecar format is replaced; a conversation whose sidecar predates this change loses its stored CLI session reference and starts that profile fresh, seeded from history exactly as the stale-resume fallback already handles today.
- Extend `AgentRuntime::run`'s return type from `Result<String, AgentError>` to `Result<AgentOutcome, AgentError>`, where `AgentOutcome` carries the final text plus a trace of every tool call attempted that turn (name and outcome: executed ok/errored, denied by standing policy, declined by the user this turn, or rejected for an unknown name or malformed arguments — the last case alone also keeps the offending arguments, capped in size, since that is the one outcome where the argument itself is the diagnostic). Nothing about tool execution, permission enforcement, or the streamed text callback changes; only what survives after `run` returns.
- Record cancellation and crashes (a dropped generation task that was never told it finished) as a real, distinct `Execution` status via an RAII guard, rather than leaving no record at all the way a `Stop` click does today.
- Wire `ContextManager` in: `build_context` is reshaped to read the prior `Execution`(s) for the same conversation (via a new `ExecutionLog` trait, implemented in the app crate alongside the existing `SessionLog`) and fold a short note about the last turn's tool activity into the assembled prompt when one exists, so a plain follow-up turn isn't blind to what a tool-calling turn just did. `record_execution` is extended to also append the `Execution` record for the turn that just completed.
- Add the ability to list, reopen, and delete past conversations: a directory scan (no new index file) producing every past conversation's first-message title and last-activity time, newest first, unbounded; opening one points the chat window at that log (cancelling any pending generation first, the same as starting a new chat already does); deleting removes a conversation's transcript and execution log together, best-effort, and is refused for the currently-open conversation. Deleting a conversation never touches an external CLI runtime's own session store (Claude Code's or Codex's) — Aemeath only forgets its own reference to a session, never the runtime's copy of it.

## Capabilities

### New Capabilities

- `execution-log`: the `Execution` record, its persisted format and lifecycle (start/end, cancellation, uniform per-turn recording, tool-call trace), and `ContextManager`'s use of it to carry tool activity into the next turn.

### Modified Capabilities

- `ai-chat`: "Session persistence" changes (the CLI-session sidecar is replaced by the execution log; `.sessions.json`'s shape is no longer part of this requirement). "Session resume with scrollback" changes (browsing and reopening older conversations is no longer out of scope). "Background completion, explicit cancellation" gains a requirement that a cancelled or crashed turn is recorded, not silently dropped. Adds a new requirement for deleting a conversation.
- `agent-runtime`: "Agent loop for tool-calling providers" changes to require that a turn's tool-call outcomes are retained after the loop returns, not just the final text.

## Impact

- `crates/fleet-snowfluff-ai/src/agent_runtime.rs`: `AgentRuntime::run`'s return type, a new `AgentOutcome`/`ToolInvocation` pair, the one call site inside the loop body that pushes each of the five tool-call outcomes.
- `crates/fleet-snowfluff-ai/src/context_manager.rs`: a new `ExecutionLog` trait beside `SessionLog`; `ContextManager::build_context`/`record_execution` signatures change to take/produce `Execution`-shaped data; `AemeathContextManager` holds both logs.
- New: an `Execution` record type and its JSON line format (`fleet-snowfluff-ai`, so `ContextManager` can depend on it without depending on the app crate).
- `crates/fleet-snowfluff/src/cli_session_store.rs`: removed; replaced by a new `execution_log_store.rs` (the `ExecutionLog` impl, append + scan-for-latest-per-profile) and a new `ExecutionRecorder` RAII guard.
- `crates/fleet-snowfluff/src/chat_commands.rs`: `ChatRuntimeState::{stored_session, cli_context, record_session}` read/write the execution log instead of `cli_session_store`; the four `run_generation*` functions construct an `ExecutionRecorder` around their work; a new `open_conversation` command sharing a helper with `new_chat_session`; a new `delete_conversation` command; `ChatStateSnapshot` gains the current `session_path`, needed by the picker UI to mark/grey out the open conversation.
- New: `crates/fleet-snowfluff/src/conversation_list.rs` (or similar) for the directory-scan listing.
- `ui/src/main.ts`: a conversation picker (list, open, delete) in the chat window.
- No new dependencies.
